title: Check an open source molecular search license
---

**An open source molecular search license covers the code only: permissive licences (MIT, Apache-2.0, BSD) put few conditions on a service or product built on the code, while copyleft licences (GPL, LGPL) attach conditions to code you distribute. The compound library carries its own licence: [ChEMBL 37 is CC BY-SA 3.0](https://mossflux.com/). [mossflux is `MIT OR Apache-2.0`](https://github.com/loruorg/mossflux), so you pick one.**

Engineers who put molecular search behind a REST endpoint, inside a product or in front of an MCP agent tool need two answers before they ship:

- the set of terms on the code;
- the set of terms on the compound library they load.

After reading, you can compare the licence terms of search tools, keep code terms apart from data terms, and audit any repository and its dependency tree before you adopt it.

> **Key Takeaways**
> - A project can change licence between releases, so record and check the exact version you ship.
> - A stack built from several components needs a check on each component and on every dependency it pulls in.
> - Ask a lawyer whether returning a share-alike library's hits inside your product counts as building upon it.
> - The licence promises nothing about exactness; an open repository lets you compare hits with a brute-force scan.

## What does an open source molecular search licence cover?

An open source molecular search licence sets what you may do with the engine's code when you run it as a service behind an API, embed it in a product you ship, or link it into a larger stack. The same licence text reads differently in each case, so start from how you will deploy.

![Illustration for What does an open source molecular search licence cover?](/blog/open-source-molecular-search-license/image-1-28b0752fca2e.webp)

The [OSI's MIT text](https://opensource.org/license/mit) grants permission "to deal in the Software without restriction" and asks that "The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software."

The OSI's [BSD-3-Clause text](https://opensource.org/license/bsd-3-clause) adds one rule: "Neither the name of the copyright holder nor the names of its contributors may be used to endorse or promote products derived from this software without specific prior written permission."

The [Apache Software Foundation's Apache-2.0 text](https://www.apache.org/licenses/LICENSE-2.0) says each contributor "hereby grants to You a perpetual, worldwide, non-exclusive, no-charge, royalty-free, irrevocable (except as stated in this section) patent license". A project offered under `MIT OR Apache-2.0` lets you take the short MIT text or the longer Apache text with that patent grant.

Copyleft adds conditions at the point of distribution. The [GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html) says "The GPL does not require you to release your modified version, or any part of it," so a private internal service triggers no release duty.

On linking, the same FAQ says that for a GPL library, "the terms of the GPL apply to the entire combination."

The [zilliztech/MolSearch README](https://github.com/zilliztech/MolSearch) lists Milvus, postgres and RDKit as separate requirements for one molecular search setup. Each is a separate component, so each must be checked before you adopt the stack, along with every dependency it pulls in.

## Which open source molecular search tools use which licence?

Indigo and mossflux both use permissive open source licences: Indigo ships under one, and mossflux lets you choose between two.

| | Indigo | mossflux |
| --- | --- | --- |
| Licence | Apache 2.0 | `MIT OR Apache-2.0` |
| Searches | Substructure, similarity | Tanimoto similarity, SMARTS substructure |
| Choice of terms | One licence | Pick MIT or Apache-2.0 |
| Earlier licence | GPL v3 at version 1.0.0 | None stated |

[EPAM's Indigo documentation](https://lifescience.opensource.epam.com/indigo/) says Indigo is distributed under Apache License 2.0. It was released under GPL v3 at version 1.0.0 and relicensed to Apache 2.0 from version 1.4.0, so a copy older than 1.4.0 carries different obligations from a current one.

Per EPAM's licence text, Apache 2.0 permits use, modification and inclusion in both open-source and proprietary products. EPAM describes Indigo as a molecular toolkit for fingerprinting, substructure search and visualisation, and says it can also run a molecular similarity search.

[The mossflux project](https://mossflux.com) describes itself as exact similarity and SMARTS substructure search over molecular fingerprints, written in Rust. Its [design page](https://mossflux.com/docs/design) says no external chemistry library is used, and that the SMILES and SMARTS parsers, perception, screen and matcher are all in its repository.

That keeps a chemistry toolkit's licence out of the code you inherit. A build still pulls in other Rust crates, so run the dependency check from `Cargo.toml` before you ship.

Indigo suits a project that wants fingerprinting, substructure search, similarity search and visualisation in one toolkit under one Apache 2.0 licence. mossflux suits a search-only engine where you choose between MIT and Apache-2.0 and no chemistry toolkit's licence comes with the code.

## Does your compound library have a separate licence?

Yes: a compound library carries its own licence, separate from the licence on the search code, so the engine and the molecules you search are covered by different terms.

[ChEMBL at EMBL-EBI](https://www.ebi.ac.uk/chembl/) releases its data under the Creative Commons Attribution-ShareAlike 3.0 Unported licence (CC BY-SA 3.0).

On share-alike, it says "you must distribute your contributions under the same license as the original."

In practice, attribution means you name ChEMBL where you show or redistribute its data. Share-alike applies when you remix, transform or build upon the material.

Whether indexing a library or returning hits inside a product counts as building upon it is a legal question, so put it to a lawyer before you ship.

The [mossflux public demo](https://mossflux.com/) runs two licences on one service. It searches ChEMBL 37 (2.9 million molecules) and labels its data "Demo data: ChEMBL 37, CC BY-SA 3.0". The engine keeps its code licence, the data keeps its own terms, and neither replaces the other.

In-house and make-on-demand libraries have their own terms:

- Your company's data policy governs an in-house collection.

- A make-on-demand supplier's terms govern its catalogue and can differ from ChEMBL's, so read them before you load that library into any search service.

For each library you plan to search, write down:

- who supplies it and under which licence or contract;
- what attribution it requires;
- whether it restricts redistribution or derived data;
- whether your service shows the data, or only returns identifiers.

## What does open source not tell you about a search tool?

Open source tells you what you may do with the code and nothing about whether results are exact, which limits apply or what the tool depends on, so each of those needs its own check.

In mossflux, exact means the same rows as a brute-force scan. The [correctness docs](https://mossflux.com/docs/correctness) say substructure search is tested against a brute-force oracle, `brute.rs`, and that 114 of 114 queries agree with RDKit in the RDKit differential.

An open repository makes that claim checkable: run any query through a brute-force scan and compare the rows yourself.

Writing the chemistry code in-house does not remove dependencies. The Rust crates mossflux uses are separate components, and each needs its own licence check.

The [mossflux API docs](https://mossflux.com/docs/api) say the fingerprints are mossflux's own and are not RDKit-compatible.

A limit in mossflux refuses a request and never changes an answer. A search that passes its deadline returns an error, never a partial list.

## How do you check a tool's licence and its dependencies?

You check a tool's licence by reading the licence file in the repository, the `license` field in its manifest, and the licence of every package in its dependency tree. For a Rust tool you need `git`, `cargo` and `jq`.

1. Read the licence files in the repository root. Clone the repository, search the top level for licence text, open each file the search prints, and note whether there is one file or two.

```sh
git clone https://github.com/loruorg/mossflux && cd mossflux
ls | grep -i -E 'licen|copying'
cat <file>
```

2. Read the manifest field. For a Rust project, `grep` the `license` line in `Cargo.toml`. A workspace can set it per crate, so check each crate you ship.

```sh
grep -n 'license' Cargo.toml
```

3. List the dependency tree. Every line of this output is code you inherit.

```sh
cargo tree
```

4. Print each package's licence. `cargo metadata` emits one JSON document, and `jq` pulls out the name, version and `license` of every package. A `null` means the maintainer declared no licence string, so open that package's source.

```sh
cargo metadata --format-version 1 | jq -r '.packages[] | "\(.name) \(.version) \(.license)"'
```

5. Check Python tools with `pip show` and read the `License` line in its output.

```sh
pip show <package>
```

6. Read dual-licence wording. The [Cargo reference](https://doc.rust-lang.org/cargo/reference/manifest.html#the-license-and-license-file-fields) says Cargo interprets the `license` field as an SPDX expression, and that with `OR` the user may choose either license. `MIT OR Apache-2.0` therefore lets you pick MIT or Apache-2.0 and follow only that one, while `AND` would apply both sets of terms.

7. Check the data and the image separately. Read the compound library's licence apart from the code. A Docker image adds base-layer licences: the mossflux [deploy docs](https://mossflux.com/docs/deploy) describe `loruorg/mossflux` as distroless and non-root, and you still read the image's own contents the same way.

If you install the CLI from source as the [CLI docs](https://mossflux.com/docs/cli) describe, run step 4 in the same checkout. You get one line per package in the build graph, and any line that doesn't match your policy is the one to read in full.

The declared field is the maintainer's claim, so read the licence text itself when the decision matters. This checklist is for engineers and is not legal advice.

## What does mossflux's MIT OR Apache-2.0 licence mean when you deploy it?

mossflux's `MIT OR Apache-2.0` licence means you pick MIT or Apache-2.0 and follow that one set of terms when you run, embed or redistribute it. [The project](https://github.com/loruorg/mossflux) lives at github.com/loruorg/mossflux, the current release is 0.1.0, and it is free, with no paid plan, hosted service or account.

`mossflux serve` answers REST and MCP on port 8080 and gRPC on 50051 over one engine, so the three transports cannot disagree (see the [API reference for REST, MCP and gRPC](https://mossflux.com/docs/api)).

The Docker image is `loruorg/mossflux` on Docker Hub. It is x86-64 only, so on arm64 you build the image from the Dockerfile. Docker Compose and Kubernetes manifests sit in `deploy/`, and the [deployment guide](https://mossflux.com/docs/deploy) covers configuration and sizing.

To build the CLI yourself, you need Rust 1.95 or later:

```sh
cargo install --git https://github.com/loruorg/mossflux mossflux-cli
```

The licence leaves three things for you to settle:

- Your library's data licence, since the code licence covers the engine and not the molecules you load into it.
- Your own canonicalisation of salts, tautomers and stereo before ingestion, because `score == 1.0` means equal bits, not the same compound.
- The other Rust crates in the dependency tree. The [design page](https://mossflux.com/docs/design) lists the chemistry code mossflux writes itself; every other crate is a separate component with a licence to check.

To see the single binary answer a query before you install anything, [try the demo](https://mossflux.com/#demo).

## Frequently asked questions

### What is an open source molecular search licence?

An open source molecular search licence is the licence a search tool's source code is released under, stated in its repository licence file and manifest. The compound library you search is licensed separately.

### Which is better for a search service, MIT or Apache-2.0?

Both are permissive, so either allows use in a product with notices kept. Apache-2.0 adds an explicit patent grant from each contributor, and with mossflux's MIT OR Apache-2.0 you pick one and follow its terms.

### Does the GPL block me from running a hosted search service?

The answer depends on the licence version and on whether you distribute copies of the software. Read the GNU GPL FAQ and the licence text for your exact version before you commit, and check the LGPL text separately.

### Is the licence on the code the same as the licence on the data?

No. The software licence covers the engine and the data licence covers the molecules you search, so the mossflux demo runs MIT OR Apache-2.0 code over ChEMBL 37 data under CC BY-SA 3.0.

### Does open source mean the search results are exact?

No. A licence says nothing about result quality, and mossflux's [correctness page](https://mossflux.com/docs/correctness) describes how its results are tested against a brute-force scan.
